# AI usage log

This log records how AI assistance was used on this project, what was kept,
changed or rejected, and which controls applied. It is written to be checked
against the Git history.

## Tool and setup

| Item | Detail |
| --- | --- |
| Assistant | Claude (Anthropic), used as an agent in a single working session on 2026-11-18 |
| What the assistant could do | Read the assignment brief, write files, run a JDK 21 compiler and shell in an isolated sandbox |

| Consequence | Framework-free domain code was compiled and its unit tests executed in the sandbox. Everything touching Spring has to be verified with `mvn verify` on the engineer's machine and by CI. See [Verification](#verification-record). |

## How tasks were defined for the AI

Each stage was specified before code was written, with intent, constraints,
acceptance criteria and technical context. The task tables in the three scenario
documents are those definitions. Standing constraints for every task:

- Java 17 language level, Spring Boot 3.3, no Lombok, constructor injection only
- Domain logic in classes with no framework imports, so it is testable alone
- SQL must run unchanged on H2 and PostgreSQL
- No behaviour without a test; no test that sleeps
- Additive, backward-compatible schema changes only
- Comments explain why, not what

## Traceability: generated, changed, rejected

### Generated by AI and kept

All source files in the first three commits were drafted by the assistant.
The commits carry a `Co-Authored-By: Claude` trailer.

### Design changed during the session, with reason

"Initial design" is what the assistant first planned or wrote; "final" is what is in the repository.

| Item | Initial design | Final | Reason |
| --- | --- | --- | --- |
| Primary key of `links` | Numeric `id` plus unique `code` | `code` is the primary key | Hot path is lookup by code; avoids driver-specific generated-key handling |
| Per-day analytics | `GROUP BY CAST(clicked_at AS DATE)` | `click_day` column set in UTC by the application | The cast depends on the database session time zone |
| Timestamp binding | `Instant` passed to JDBC | `java.sql.Timestamp` with explicit SQL type | PostgreSQL's driver does not accept `Instant` |
| Redirect route | `/{code:[A-Za-z0-9_-]{4,32}}` | `/{code:[A-Za-z0-9_-]+}` plus a length check in code | Avoided relying on nested-brace regex parsing in route patterns that could not be compiled and tested in the sandbox |
| URL policy | Dotted-quad private IP check | Added numeric-only host rule (`http://2130706433/`) and IPv6 unique-local range | Review found the bypass |

### Proposed and rejected

| Proposal | By | Rejected because |
| --- | --- | --- |
| Switch the project to Python/FastAPI | AI | Engineer's decision, see session record #3 |
| `DELETE /api/v1/links/{code}` | AI (first API sketch) | Without authentication anyone could delete any link |
| JPA/Hibernate entities | AI (considered) | Six SQL statements; the atomic increment and aggregations would be native queries anyway |
| Sequential base62 IDs | AI (considered) | Enumerable |
| Check alias availability with SELECT before INSERT | AI (considered) | Race condition between concurrent requests |
| Hard-delete links at the moment of expiry | AI (considered) | Loses the 410 signal and the final analytics; allows instant alias hijack |
| Global retention policy as the reading of "links shouldn't live forever" | AI (considered) | Destructive and a product decision; needs sign-off |
| Reading `X-Forwarded-For` in the rate-limit filter | AI (considered) | Client-controlled header; trust belongs in platform configuration |
| Alias format as a `@Pattern` annotation plus a separate reserved-word check | AI (considered) | Two places for one rule; both went into `AliasPolicy` with one unit test |
| JaCoCo coverage plugin | AI (considered) | A plugin that could not be run in the sandbox is a build-break risk for no functional gain; coverage reporting is a next step |

## Quality gates

| Gate | Mechanism |
| --- | --- |
| Static analysis | `javac -Xlint:all` on every build |
| Unit tests | JUnit 5, domain package, no Spring context |
| Integration tests | Full application through MockMvc on Flyway-migrated H2 |
| Schema | Migrations are applied from scratch in every test run |
| Security review | URL policy threat cases are unit tests; no secrets in the repository; dependency updates through Dependabot |
| Performance | Redirect path reviewed: one cache read or one primary-key lookup, no synchronous write. Not load tested (see limitations) |
| CI | GitHub Actions runs `mvn verify` on every push and pull request |

## Secure AI usage

- No credentials, tokens, customer data or proprietary source code were given to
  the assistant. The only inputs were the assignment brief and the instructions above.
- The only credentials in the repository are local-only defaults for the Docker
  Compose PostgreSQL container, labelled as such.
- AI-written code was treated as untrusted until built and tested: nothing is
  described as verified unless the verification record below says how.
- Dependencies were limited to well-known libraries with versions managed by the
  Spring Boot BOM where possible, to reduce the risk of an invented or
  mistyped package name.

## Human sign-off points

Changes that need an explicit human decision rather than an AI default:

| Change | Why |
| --- | --- |
| Any schema migration | Irreversible in production once data exists |
| Setting a default TTL or shortening retention | Changes what happens to users' links |
| Enabling trust of forwarded headers | Wrong setting lets clients spoof their address and bypass the rate limit |
| Relaxing the URL policy | Security control |
| Dependency major-version upgrades | Behavioural change |
